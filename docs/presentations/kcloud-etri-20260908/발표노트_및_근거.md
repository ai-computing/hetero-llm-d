# K-Cloud ETRI 성과·협업 발표 노트

총 4장, 약 5분. 텍스트·도형은 편집 가능하며 2장에 원본 GIF가 삽입돼 있습니다.
PDF와 미리보기는 같은 레이아웃 데이터로 생성한 정적 참고본입니다. PowerPoint 자체 렌더링 결과는 아닙니다.

## 1장

발표 요지 (약 60초)
ETRI는 K-Cloud 자원관리 연구를 위해 세 가지 기반을 진행했습니다. 첫째는 서로 다른 GPU와 NPU를 연결한 서빙 환경, 둘째는 이를 한 화면에서 관측하고 운영하는 lmd-top, 셋째는 다른 서버에서 수행한 실제 KV 이송 기반 이기종 NPU PD 실험입니다. 이 세 축을 공동연구 정책의 구현·비교에 활용하는 것이 오늘 논의 목적입니다. 세 작업이 완전히 자동화된 폐루프로 통합됐다는 뜻은 아닙니다.

근거: README.md, docs/ENVIRONMENT-GUIDE.md, lmd-top/README.ko.md, lmd-top/CHANGELOG.md, PD disaggregation_HISTORY.md §§1,4,6,12.
PD 자료는 다른 서버의 작업 이력을 사용자가 제공한 문서로 확인했습니다. 원격 원본 코드나 원시 JSONL을 이 PPT 제작 중 다시 검증하지 않았습니다. 현재 전체 시스템 상시 가동 또는 연구용 플랫폼 제공 확약을 의미하지 않습니다.

## 2장

발표 요지 (약 70초)
llm-d 기반으로 가속기별 모델 서버와 모델별 InferencePool/EPP 라우팅을 구성했습니다. lmd-top은 모니터에서 출발해 컴파일·배포와 운영 액션까지 확장했습니다. EPP 확장 플러그인은 실제 엔드포인트별 composite score를 Prometheus로 노출하고, lmd-top에서 해당 값을 연결해서 볼 수 있게 합니다. 연구자가 배치나 라우팅 정책을 제안하면, 어떤 요청 경로에서 어떤 자원 병목이 생기는지 확인할 관측점이 있다는 의미입니다.

GIF: docs/images/lmd-top-ppt.gif, 1806×1075, 25.14초, 무한 반복. 실제 구성 스냅샷을 바탕으로 lmd-top --cast가 수치 변화를 합성했습니다. 실측 성능·실제 부하 영상으로 해석하지 않습니다. PPTX에는 원본 GIF가 포함되고 PDF에는 첫 프레임만 표시됩니다.

근거: lmd-top/README.ko.md, lmd-top/CHANGELOG.md v0.35.0·v0.36.0, lmd-top/contrib/epp-score-observer/README.md (2026-07-08 클러스터 검증 기록), manifests/README-model-store.md, manifests/epp/README.md. 모든 모델이 EPP를 경유하는 것은 아니며, 데이터 표시는 exporter 및 트래픽 조건에 의존합니다. 자동 최적화 컨트롤러가 완성됐다는 의미는 아닙니다.

## 3장

발표 요지 (약 90초)
다른 서버에서는 공식 엔진 벤치에서 시작해, 자체 런타임으로 KV를 직접 소유하고 실제로 전달하는 단계까지 진행했습니다. 초기의 재프리필 모사와 달리 prefill이 만든 KV를 받아 decode를 이어갑니다. RNGD와 ATOM의 prefill/decode 역할을 교환하는 네 조합, 실제 출력 정합 검증 기록, llm-d 게이트웨이 측정 기록이 있습니다. 슬라이드의 공유 메모리는 현재 서빙 구조이며 별도 TCP 커넥터 검증도 기록돼 있습니다. NIXL·장치 직접 전송 완성을 뜻하지 않습니다.

왼쪽 수치: 제공 문서 §5.4, 42f3e78 (2026-08-25) 커밋의 후속 게이트웨이 측정 기록. B=4, 각 조건 20표본, TPOT 27.00→20.10ms, 감소율 (27.00-20.10)/27.00=25.56%. 해당 절 커널 조건은 S=256·32레이어지만 HTTP 측정의 전체 입력 메타데이터는 별도 확인하지 않아 슬라이드에서 추가하지 않았습니다. TPOT는 배치로 나눈 ms/token과 다릅니다.

오른쪽 수치: 제공 문서 §6.5, 384310c의 동일 배치·closed-loop 조건 재측정 기록. N=8, 출력 100~160, solo 1카드 106.6 tok/s, PD 2카드 143.7 tok/s. 카드당 각각 106.6과 71.85 tok/s이므로 solo가 약 1.48배 높았습니다. 후속 KV·컴파일 최적화 전 결과이고 왼쪽 A/B와 다른 버전·실험입니다. 전체 처리량 이점과 카드당 효율의 trade-off를 보여주는 사례일 뿐 모든 PD가 비효율적이라는 결론이 아닙니다.

근거 문서: PD disaggregation_HISTORY.md §§4,5.4,6,7,11. 이번 제작에서는 다른 서버의 원시 결과를 직접 확인하거나 재측정하지 않았습니다.

## 4장

발표 요지 (약 75초)
교수님의 전문 분야에 따라 세 가지 협업 경로를 제안할 수 있습니다. 첫째, 입력·출력 길이와 도착 부하에 따라 Solo/PD와 가속기 역할을 고르는 배치 정책입니다. 둘째, 실제 KV 이송 경로의 중첩과 슬롯별 KV 구조 개선으로 continuous batching의 비용을 줄이는 시스템 연구입니다. 셋째, 관측값과 운영 액션을 연결해 지연 목표를 만족시키는 라우팅·스케일 제어입니다.

우선 공동 실험은 공통 워크로드와 동일 버전의 측정으로 Solo/PD 선택 경계를 만드는 것으로 제안합니다. SLO는 서비스 수준 목표, TTFT는 첫 토큰 지연, TPOT는 토큰 간 생성 지연, tok/J는 에너지 효율입니다. 카드당 효율과 전체 처리량을 함께 비교하고 commit·artifact·batch·scheduler·prefetch를 기록해야 합니다.

이 슬라이드는 협업 제안이며 연구 분담·플랫폼 제공·성능 개선의 확약이 아닙니다. 최신 통합 스윕, 전력 집계 정의 통일 및 현재 운영 상태 재확인이 필요합니다. 원격 문서의 §12는 continuous batching 개선, NIXL backend 및 장치 직접 전송을 미완료로 구분합니다.

근거: PD disaggregation_HISTORY.md §§6.4,6.5,7,11,12; lmd-top/README.ko.md; lmd-top/contrib/epp-score-observer/README.md.
