# ETRI NPU 특성과 모델·자원 관리

본문 11장 + 부록 2장.

## 1장

과제 배경 설명 없이 실제 구축 환경에서 시작합니다. 아이콘은 특정 카드 외형을 복제한 제품 사진이 아니라 장비 종류를 구분하는 편집 가능한 도형입니다. 실제 환경에는 CPU 워커, 관리 노드, 모니터링, 공유 NAS가 있습니다. 여기서는 GPU·Furiosa·Rebellions와 모델 생애주기를 중심으로 추상화했습니다. Gateway가 디바이스에 직접 요청하는 것이 아니라 모델 서버에 연결합니다. 이 그림은 논리 구성이고 모두 현재 가동 중이라는 뜻이 아닙니다. lmd-top은 관측·운영 도구이며 트래픽 프록시가 아닙니다.

근거: docs/ENVIRONMENT-GUIDE.md; manifests/README-model-store.md; lmd-top/README.ko.md; 2026-09-08 클러스터 조회

## 2장

GPU도 JIT·그래프 컴파일 등을 사용할 수 있습니다. GPU에는 컴파일이 없고 모든 NPU가 동일한 사전 컴파일 방식이라는 뜻이 아닙니다. 여기서 GPU 경로는 사용한 vLLM 계열 일반 배포 흐름, NPU 경로는 사용한 RBLN/Furiosa 컴파일·아티팩트 기반 경로입니다. Furiosa는 사전 컴파일된 산출물을 가져오는 경우도 있습니다. 모델·타깃·길이·배치 등 조건은 엔진마다 다릅니다. 비교는 성능·가격·전력의 벤더 우열을 주장하지 않습니다.

근거: manifests/README-model-store.md; manifests/compile-*.py; PD disaggregation_HISTORY.md §§3.1–3.2,5.4,8

## 3장

버킷은 실행에 사용하는 입력/배치 크기 등의 미리 정해진 규격을 의미합니다. 제공 문서의 §3.2가 원본 JSONL을 확인해 요약한 값입니다. coarse TTFT88.12/TPOT16.48/output59.7, fine27.85/16.29/61.1, preset22.08/16.34/61.1. 세 조건 모두 shape_exact=true, 실패0. 이 PPT 제작에서 원시 JSONL이나 NPU 실험을 다시 실행하지 않았습니다. 특정 길이·동시성 조건의 비교이며 모든 길이에 일반화하지 않습니다. 전력/토큰당 에너지를 측정한 하니스도 있으나 GPU와 같은 조건의 우열 비교를 여기서 제시하지 않습니다.

근거: PD disaggregation_HISTORY.md §§3.1–3.3,11

## 4장

예시는 PD 문서 §5.3의 2026-08-19 기록: RNGD B=4 serving engine, lm_head를 host에서 device로 이동하여 78.86→26.91ms/step. lm_head는 다음 토큰 점수를 계산하는 출력 연산으로 설명합니다. 커널/엔진의 step 비용이며 API E2E latency 또는 배치로 나눈 token당 비용이 아닙니다. 다른 별도 기록으로 resident KV48.2→16.3ms/token 및 배치 디코드 B1/B4/B8 비교가 있습니다. 각 개선은 별도 조건이므로 합산하지 않습니다. 이런 데이터 이동·배치 민감성이 NPU에만 존재한다고 주장하지 않습니다.

근거: PD disaggregation_HISTORY.md §§5.1,5.3,7,11

## 5장

이 장은 기능과 요구의 논리적 대응이며, 이 PD 벤치가 lmd-top 개발 이전에 수행되어 제품 요구사항을 역사적으로 도출했다는 뜻은 아닙니다. lmd-top 개발(6~7월)과 PD/벤치 작업(8월)은 서로 다른 작업 흐름이었습니다. 이번 기술 소개에서 공통 자원관리 맥락으로 연결합니다. lmd-top이 세부 커널 병목을 자동 진단하거나 자동 최적화하는 것은 아닙니다. 구현된 모델 준비/배포 및 기존 exporter와 API 기반 관측 기능 범위로 설명합니다.

근거: lmd-top/README.ko.md; lmd-top/CHANGELOG.md; PD disaggregation_HISTORY.md

## 6장

실제 기능: Library/Model List에서 catalog 가능성 및 store builds 확인, Zoo에서 벤더 모델 탐색/prefetch, Compile 폼에서 RBLN/Furiosa 조건 선택 및 Job 생성, Activity에서 compile/prefetch/deploy 진행 상태 확인, Deploy에서 노드의 할당 기준 용량과 타깃 선택. 컴파일은 벤더 도구를 실행하는 작업이며 lmd-top 자체가 compiler가 아닙니다. apply/운영 액션은 권한 모드 및 확인 흐름을 따릅니다. 모든 모델/파라미터 조합이 지원된다는 뜻은 아닙니다.

근거: lmd-top/README.ko.md; lmd-top/CHANGELOG.md v0.34–0.36; manifests/README-model-store.md

## 7장

GIF는 실제 구성 스냅샷을 바탕으로 수치 변화와 선택을 합성한 UI 데모입니다. 성능 자료가 아닙니다. 기존 전체 뷰 순환 녹화라 발표자는 주요 화면에서 Serving/Traffic/Infra의 의미만 짚습니다. EPP endpoint score는 별도 개발한 score observer 플러그인이 제공하고 lmd-top은 pod 단위로 연결합니다. exporter·트래픽·권한에 따라 표시 가능한 지표가 다릅니다. 현재 데이터가 없는 칸은 자동적으로 추론한 값이 아닙니다.

근거: lmd-top/README.ko.md; contrib/epp-score-observer/README.md; docs/images/lmd-top-ppt.gif

## 8장

다른 서버에서 수행한 연구 기록을 근거로 합니다. 공식 엔진에서 당시 KV export/import 훅이 없던 제약을 우회하려고 자체 KV 입출력 런타임을 구성했습니다. 실제 전달받은 KV로 decode를 이어가는 구현이며 초기 재프리필/캐시 에뮬레이션과 구분합니다. 기본 서빙 경로는 shared /dev/shm이고 별도 TCP 전송 테스트 기록이 있습니다. NPU A/B는 카드 역할로, 서로 다른 서버 간 직접 전송을 단정하지 않습니다. 자체 런타임 전체를 lmd-top이 자동 제어하는 통합 제품을 완성했다는 뜻은 아닙니다.

근거: PD disaggregation_HISTORY.md §§4,6.1,12

## 9장

원문 §6.5의 384310c 재측정 기록. solo1card106.6 vs PD2card143.7tok/s, 출력100~160, in-flightN8, 동일 배치/closed-loop 조건. 카드당 PD71.85=143.7/2이며 solo가 약1.48배. 네 벤더 조합 스윕과 이 solo 비교는 별도 실험으로, 그래프가 네 벤더 조합의 비교라는 뜻은 아닙니다. 최신8/25최적화 전 기록. 모든 PD나 모든 요청에서 solo가 유리하다는 일반화 금지. 처음 불공정 비교는 철회됐고 이 값은 후속 동일 배치 대조군 기록입니다. 원문 commit 기록을 인용했고 PPT 제작 중 원시데이터를 재검증하지 않았습니다.

근거: PD disaggregation_HISTORY.md §§6.2,6.5,11

## 10장

세 작업의 논리적 관계를 나타냅니다. 모든 작업이 하나의 자동화 시스템으로 end-to-end 통합됐거나 분석→도구→런타임의 순서로 개발됐다는 뜻은 아닙니다. 직접 완료 근거가 있는 벤치·관측/운영도구·실제KV이송실험을 하나의 자원관리 논의로 묶습니다.

근거: lmd-top/README.ko.md; PD disaggregation_HISTORY.md §§1,12

## 11장

공동연구 제안이며 역할 분담이나 시스템 제공을 확약하지 않습니다. 현재 구현에 연구 정책을 연결하려면 최신 설정 통합 스윕, 메타데이터 정합, 운영 상태 재확인 등이 필요합니다. 관측 기반 자동 제어 전체는 앞으로의 연구 후보로 구분합니다.

근거: PD disaggregation_HISTORY.md §§11,12; lmd-top/README.ko.md

## 12장

기존 조회: GPU GB10 2서버각1; npu-node-1 ATOM4 RNGD2 GPU0; ESC8000 RNGD4 SchedulingDisabled; cpu-3NotReady. Gateway Programmed=True. 모델워커0/0이며 gateway 가동을 추론 성공과 혼동하지 않습니다. NAS·공유저장소는 환경 가이드 기록이며 이번 새로 검증하지 않았습니다.
