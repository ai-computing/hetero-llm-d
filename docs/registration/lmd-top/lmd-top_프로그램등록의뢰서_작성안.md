## 3. 프로그램 개요서

### 프로그램 종류코드

시스템 S/W > 유틸리티 > 기타 유틸리티 S/W

### 1. 적용분야

Kubernetes 기반 LLM 추론 서비스 운영·성능 관측 및 GPU/NPU 통합 자원 관리

### 2. 주요내용 — 특징

본 프로그램은 대규모 언어모델 추론 서비스의 요청 전달 경로, 모델 실행 상태 및 이종 AI 가속기 자원을 서로 연결하여 관측하고 운영하도록 구성한 터미널 기반 소프트웨어이다. Kubernetes 리소스 정보와 Prometheus 성능 지표를 수집·정규화한 뒤, Gateway, EPP, 모델 서버, GPU/NPU 사이의 관계를 따라 상태와 성능을 탐색할 수 있도록 표현한다. 이를 통해 특정 모델의 지연 증가를 요청 분배, 대기열, 캐시 사용량 및 가속기 상태와 연계하여 분석할 수 있다. 또한 동일 모델을 원본 가중치, 벤더별 컴파일 산출물, 실행 중인 배포로 구분하면서 하나의 모델 계열로 묶어, 컴파일 준비부터 배포와 운영까지의 정보를 연결한다. NVIDIA GPU, Rebellions RBLN 및 Furiosa RNGD를 공통 화면에서 관측하되 장치별 지원 지표와 컴파일 특성을 반영하며, 실제 자원 할당에 근거한 배치 가능성을 제시한다. 관측 결과를 바탕으로 선택한 대상에 운영 작업을 수행하는 흐름과 권한 모드, 사용자 확인 및 감사 기록을 결합한 점이 특징이다. 터미널 화면과 기계 판독용 JSON 출력을 함께 제공하여 운영자의 대화형 관리와 외부 자동화 도구의 상태 활용을 지원한다.

### 2. 주요내용 — 주요기능

1) 추론 서비스의 계층 간 연계 조회: Gateway에서 HTTPRoute, InferencePool, EPP, 모델 서버 및 실행 노드로 이어지는 관계를 표시하고, 선택한 대상의 관련 리소스와 성능 정보를 탐색한다. 요청이 EPP를 경유하는지 우회하는지도 진단한다.
2) 이종 GPU/NPU 자원 통합 관측: NVIDIA GPU, Rebellions RBLN, Furiosa RNGD의 사용률, 메모리, 온도, 전력 등 수집 가능한 지표를 장치별로 표시한다. 노드별 가속기 수량과 Kubernetes 자원 요청량을 함께 반영하여, 장치가 쉬고 있는 상태와 새 작업을 배치할 수 있는 상태를 구분한다.
3) 추론 성능 및 라우팅 분석: 모델별 토큰 처리량, 요청 대기, 첫 토큰 지연(TTFT), 토큰당 지연(TPOT), 전체 응답 지연 및 KV 캐시 상태를 조회한다. EPP의 scorer·가중치·picker 설정과 파드별 요청 분배를 연결하여 보여주며, 계측 확장이 제공하는 endpoint score와 가중치 변경 가정에 따른 분석을 지원한다.
4) 모델 원본·컴파일본·배포의 연계 관리: 모델 카탈로그와 공유 스토어의 산출물을 모델 계열별로 묶어 표시한다. 가중치 사전 다운로드, 벤더별 NPU 컴파일 옵션 설정, 컴파일 Job 및 서빙 배포 매니페스트 생성, 배치 대상 선택과 적용을 지원한다.
5) 실행 이력 기반 운영 진단: 컴파일 진행 상태와 실패 로그를 분석하고 실행 결과, 옵션 및 확인 가능한 도구 버전을 기록한다. 축적된 이력에서 반복 실패와 성공 조건을 찾아 후속 컴파일 설정 검토에 활용한다.
6) 확인 절차를 갖춘 운영 제어: 권한 모드에 따라 배포 규모 조정, 재시작·롤백, 노드 스케줄링 제한, 라우트 편집 및 리소스 삭제를 제공한다. 변경 작업은 사용자 확인을 거쳐 수행하고 대상과 결과를 감사 로그에 남긴다.
7) 외부 도구 연계 및 환경 점검: 관측 상태를 텍스트와 JSON으로 출력하며, 플랫폼 전제조건 점검, 로그·YAML 조회 및 터미널 화면 기록을 지원한다.

### 2. 주요내용 — 사용방법

1) 관리 호스트에 lmd-top과 kubectl을 설치하고 대상 Kubernetes 클러스터의 kubeconfig를 설정한다.
2) LMD_NS에 namespace, LMD_PROM에 접근 가능한 Prometheus의 host:port를 지정한다.
3) lmd-top을 실행하여 섹션·서브탭을 이동하며 서비스와 자원 상태를 확인한다.
4) 운영 변경이 필요한 경우 --mode admin으로 실행하고, 대상 선택 후 매니페스트·변경 내용을 확인하여 적용한다.
5) --json 또는 --snapshot으로 상태를 출력하고 --audit로 작업 이력을 확인한다.
예시: LMD_NS=llm-serving LMD_PROM=127.0.0.1:9090 lmd-top
예시: lmd-top --mode admin / lmd-top --json
